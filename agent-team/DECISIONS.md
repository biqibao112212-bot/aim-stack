# 火控与云台控制关键决策

上下文版本：`CTX-FIRE-CONTROL-GIMBAL-2026.07-v1`

1. 火控与云台控制使用独立分支 `research/fire-control-gimbal` 和独立 worktree，
   以允许 `main` 上的预测器研究并行推进；两边私有 Agent Team 上下文互不复制。

2. 本分支从正式 `aim-stack/main` 的 `464605c` 开始。旧共享仓库中的
   `feature/auto-aim-fire-control` 只作历史取证，不复用为正式分支，不整体合并，
   也不恢复其混合模拟器仓库布局。

3. 模拟器依赖固定为 Simulator 1.0.3 / DaedalusSimSdk 1.0.0。模拟器仅是未来
   集成与验收依赖，不是本阶段研究对象；消费者侧继续遵守已发布 SDK 与版本锁。

4. 本分支所有权从上游预测/tracker 输出之后开始。预测器训练与结构默认冻结，
   只有经明确讨论批准的最小接口适配才可进入本分支。

5. 现存 FireControl、二阶位置 MPC、planner 和固定频率云台命令环是待审计基线，
   不是已经验收的方案。旧记录中的 50 ms 发射槽、幂等事件和失败关闭原则属于
   候选安全约束，必须结合当前代码和目标重新确认后才能冻结为正式合同。

6. 坐标或控制效果问题不得通过未经证明的 pitch/yaw 反号、经验偏置或 tracker
   调参掩盖。相关修改必须先满足模块坐标合同并通过聚焦回归测试。

7. 研究采用顺序隔离设计。阶段一固定干净预测器输入，只优化云台与火控，并在
   20 Hz 最大射频约束下测量实际射频和命中率；阶段二固定已验收的同一火控方案，
   只改变预测器输出质量。禁止通过联合调参模糊控制器与预测器的效果归因。

8. 20 Hz 是硬上限而非预设的可达结论。正式结果必须区分 fire advice、请求命令、
   实际发射事件和命中事件；实际射频只能由实际发射事件与明确的有效交战时间计算。

9. 命中率的基本分母是实际发射事件。每次命中必须能够关联到具体发射事件；槽位、
   advice 或未执行命令不得计入发射数。零发射、高命中率和高射频、低命中率都必须
   在射频—命中率前沿中显式呈现，不能只优化单一指标。

10. 第二阶段比较要求火控实现、参数、场景、发射上限和随机条件冻结并具有可验证
    标识。预测器质量作为唯一实验变量，具体误差维度和分级在阶段零合同中冻结。

11. 模拟器默认使用 Release 1.0.3 的高性能模式；运行错误先查发布版 README、
    接口、场景控制和性能文档。消费者分支不重编译或修改模拟器源码、SDK、启动器
    和正式 Release。原生靶场仅通过 SDK `SceneControlClient` 切换。

12. 静态弹道的唯一几何标定来源是坐标合同规定的完整 camera→gimbal SE(3)
    外参。禁止用经验 `H`、pitch/yaw 反号、距离查表或任意中心偏置掩盖坐标或弹道
    误差。若实测残差显示需要补偿，先向用户提交距离分层证据、根因和建议再审批。

13. 静态验收目标是多个距离上的装甲板正中心，而不只是碰撞命中。正式试验前必须
    确认 SDK 能提供发射事件、命中点和装甲板中心的可关联真值；接口不足不能通过
    读取模拟器私有结构或修改 Release 绕过。

14. 仅把未来预测替换为物理真值并不保证 100% 命中：如果未来轨迹仍锚定于 PnP
    当前位置，PnP 平移/姿态误差、目标关联、曝光到发射延迟、弹道模型和云台跟踪
    误差都会保留。真值实验因此至少分为三臂：现有预测；PnP q0 加真值未来增量；
    真值 q0 加真值未来。三臂共同区分预测误差、PnP 锚点误差和下游控制/弹道误差。

15. 2026-07-26 的正式动态基线固定为原生 Shooting Range、3 号靶、5 m、
    30 deg/s、自瞄 B/TensorRT、`fire_control`、高性能隐藏模式。SDK 场景 ACK、
    exact-exposure truth、TCP、250 Hz 控制和实际发射均通过；模拟器采集丢帧和 GPU
    map 错误均为 0。

16. 旧启动路径默认逐帧写 `pipeline.jsonl` 会把同步 finalize 从约 0.2 ms 放大到约
    18.3 ms，并造成约 42% detector mailbox 覆盖；这属于诊断 I/O 对被测系统的
    扰动，不代表 TensorRT 内核退化。默认火控启动路径禁止 pipeline JSON/JSONL、
    Stage3、FOV JSONL 和 detector profiler；逐帧记录只能通过 `-FullTelemetry`
    或专用预测器采集脚本显式启用。

17. 2026-07-27 无 pipeline I/O 的 30 秒窗口为：完整视觉 105.768 Hz、流水线
    7.187 ms、物理 250.008 Hz、186 发/30.027 s 即 6.194 Hz、聚合 `accurate`
    184/186 即 98.92%。检测覆盖、采集丢帧和 GPU map 错误均为 0。此前 63.1 Hz
    的所谓 summary-only 结果仍被底层默认回退写入 `build/debug/aim_pipeline.json`，
    已判为受 I/O 干扰的废弃证据。

18. 当前消费者实际火控弹速是 22 m/s，而 Release 1.0.3 弹丸配置是 25 m/s。
    先保留该不一致作为无补偿基线；后续若要对齐 25 m/s，按物理参数契约 A/B 提交
    用户确认，不得用 pitch/yaw/距离经验偏置替代。

19. `fire_advice` 不是逐发发射事件。R3 正式窗口的 1534 个视觉结果中，目标有效
    761 帧、`fire_advice` 492 帧；其中 68 帧属于 burst mechanical hold，但 advice
    仍为真。实际射频只使用模拟器 `launch_count` 在稳定窗口的增量；逐发间隔、命中
    关联和中心误差在 SDK v1 下不可恢复。

20. 正式集成依赖升级为 Simulator 1.0.3 / SDK 1.0.0；1.0.2 因无窗口零等待循环造成
    readback/TCP 排队和 exact-exposure 失败而废弃。1.0.3 的 5 m 原生 Shooting Range
    静止 3 号靶验收为 151 发/151 个聚合 `accurate`，45 秒全窗口 3.356 Hz、首发至末发
    活跃段 6.708 Hz，中位逐发间隔 120 ms、P95 324 ms。后半段检测器持续失去目标，
    因而当前射频损失主要来自视觉/tracker/fire-advice 占空比，不是 19.2308 Hz 的模拟器
    物理饱和上限；聚合 `accurate` 仍不等价于装甲板正中心命中。
