# 火控与云台控制关键决策

上下文版本：`CTX-FIRE-CONTROL-GIMBAL-2026.07-v1`

1. 火控与云台控制使用独立分支 `research/fire-control-gimbal` 和独立 worktree，
   以允许 `main` 上的预测器研究并行推进；两边私有 Agent Team 上下文互不复制。

2. 本分支从正式 `aim-stack/main` 的 `464605c` 开始。旧共享仓库中的
   `feature/auto-aim-fire-control` 只作历史取证，不复用为正式分支，不整体合并，
   也不恢复其混合模拟器仓库布局。

3. 模拟器依赖固定为 Simulator 1.0.1 / DaedalusSimSdk 1.0.0。模拟器仅是未来
   集成与验收依赖，不是本阶段研究对象；消费者侧继续遵守已发布 SDK 与版本锁。

4. 本分支所有权从上游预测/tracker 输出之后开始。预测器训练与结构默认冻结，
   只有经明确讨论批准的最小接口适配才可进入本分支。

5. 现存 FireControl、二阶位置 MPC、planner 和固定频率云台命令环是待审计基线，
   不是已经验收的方案。旧记录中的 50 ms 发射槽、幂等事件和失败关闭原则属于
   候选安全约束，必须结合当前代码和目标重新确认后才能冻结为正式合同。

6. 坐标或控制效果问题不得通过未经证明的 pitch/yaw 反号、经验偏置或 tracker
   调参掩盖。相关修改必须先满足模块坐标合同并通过聚焦回归测试。

7. 研究采用顺序隔离设计。阶段一固定干净预测器输入，只优化云台与火控，并在
   20 Hz 最大射频约束下测量实际射频和命中率；阶段二固定已验收的同一火控方案，
   只改变预测器输出质量。禁止通过联合调参模糊控制器与预测器的效果归因。

8. 20 Hz 是硬上限而非预设的可达结论。正式结果必须区分 fire advice、请求命令、
   实际发射事件和命中事件；实际射频只能由实际发射事件与明确的有效交战时间计算。

9. 命中率的基本分母是实际发射事件。每次命中必须能够关联到具体发射事件；槽位、
   advice 或未执行命令不得计入发射数。零发射、高命中率和高射频、低命中率都必须
   在射频—命中率前沿中显式呈现，不能只优化单一指标。

10. 第二阶段比较要求火控实现、参数、场景、发射上限和随机条件冻结并具有可验证
    标识。预测器质量作为唯一实验变量，具体误差维度和分级在阶段零合同中冻结。
